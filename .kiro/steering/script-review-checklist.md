# 롱폼 스크립트 검토·수정 체크리스트 — 헬마드

기존 스크립트를 재검토·개선할 때 이 항목들을 순서대로 점검한다.
(신규 작성 규칙은 `script-writing.md`, 이 문서는 **완성본 다듬기/리라이팅용**)

## 잘된 예시 기준
- **`script/longform/v7_...더늦기전에당장달려야하는과학적이유.md`** 를 기준 샘플로 삼는다.
- 특징: 강한 오프닝 훅 → 인사 → 계단식 반전 전개 → 센스 있는 비유 → 체감 수치.

## ① 오프닝 (가장 자주 틀리는 지점 — 최우선)
- [ ] **첫 문장이 훅인가?** 공감 상황 묘사나 인사로 시작하면 안 됨. 궁금증·불안·통념깨기 한 방으로 연다.
- [ ] **인사("안녕하세요, 헬스 건강 정보 헬마드입니다")가 있는가?** 훅 바로 뒤에 와야 한다. 통째로 빠뜨리는 실수 잦음.
- [ ] 훅이 **결론을 공개**해버리지 않았는가? "통념이 틀렸다"까지만, "그럼 정답이 뭐냐"는 본론으로.
- [ ] 인사 직후 공감("나 얘기다") + 미끼 수치 1개 + "끝까지 봐야 답 나온다" 유도가 있는가?
- [ ] "~라면요?" 조건문 훅 남용 안 했는가?

## ② 정보 노출 속도 (시청지속 — 필수)
- [ ] **서론에서 핵심 결론·해법·구체 수치를 미리 다 줘버리지 않았는가?** (제일 흔한 개선 포인트)
  - 서론은 "무엇이 문제인지, 통념이 왜 틀렸는지"까지만. 정답·방법·핵심 수치는 본론 뒤로 재배치.
- [ ] 본론이 계단식인가? (문제 제기 → 원리 → 부위/종목별 전개 → 그제서야 실전 수치)
- [ ] 궁금증 → 해소 → 새 궁금증 리듬이 유지되는가?

## ③ 흐름·구성 (지루함·비약 점검)
- [ ] 중반부가 교과서처럼 밋밋하게 예측 가능하지 않은가? 각 파트를 **반전·의외성으로 열면** 지루함이 준다.
- [ ] 논리 비약 없는가? (근거 없이 결론으로 점프하는 구간)
- [ ] 같은 말 반복·군더더기 없는가? 한 문장에 메시지 하나.

## ④ 센스·비유 (뻔함 탈피)
- [ ] 어려운 개념을 **일상 비유**로 풀었는가? (예: 텔로미어=신발끈 캡, BDNF=뇌세포 비료, 성장신호=이틀 만에 꺼지는 알람)
- [ ] **비유를 한 번 쓰고 버리지 말고 끝까지 활용했는가?** 좋은 비유는 확장하면 이해가 쉬워지고 분량도 채워진다. (예: "이틀 만에 꺼지는 알람" → "월요일 한 번이면 닷새는 알람 꺼진 채 방치 / 월·목 두 번이면 주중에 알람 한 번 더 켜주는 셈")
- [ ] "오 이건 몰랐네" 싶은 반전 프레이밍이 최소 1개 있는가? (예: "달리기는 다리 운동이 아니라 머리 운동")
- [ ] 전문용어 남발 안 했는가? 쉬운 말로 바꿨는가?

## ⑤ 수치·근거
- [ ] 구체 수치/연구 5개 이상. 서론 1개(미끼), 본론 각 파트 1개 이상.
- [ ] 체감되는 숫자인가? ("16년 젊은 몸", "3년 더 김", "2.6배")
- [ ] 실재하는 연구인가? (지어내지 않음, **웹 검색으로 실제 수치 확인**)
- [ ] **근거가 얇지 않은가? (깊이 점검)** "연구에 따르면 ~더 좋다"로 뭉뚱그리지 말고, 가능하면 **비교 수치**를 붙인다. (예: "주 2회가 주 1회의 거의 두 배 효과크기", "주 5세트 미만은 근비대 5% 남짓, 충분히 쌓으면 몇 배") — 이런 대조 수치가 설득력·분량을 동시에 채운다.

## ⑥ 말투·형식
- [ ] ~다/~데요/~고/~죠 말투. ~해요/~하세요 여성형 없는가?
- [ ] 기계적 넘버링("첫째,") 대신 구어체 전환("자, 첫 번째")인가?
- [ ] **서론 마무리는 "쉽고 빠르게 살펴보겠습니다" 류 헬마드 정형 톤으로.** "끝까지 봐야 진짜 답 나온다 / 놓치지 마세요" 같은 노골적 낚시성 시청유도 문구는 지양(작위적으로 느껴짐). 시청 유도는 훅·공감에서 이미 걸었으니, 서론 닫는 문장은 담백하게 본론 예고로 마무리.
- [ ] 마무리에 구독 멘트 있는가? ("오늘 영상 내용 유익하셨다면 구독, 좋아요, 알림 설정, 하이프까지 꼭 부탁드리구요, 헬마드 구독자 여러분 오늘도 득근하는 하루 되시기 바랍니다.")
- [ ] 줄글(스크립트 형태)인가? 항목화·화면설명·타임스탬프 없는가?

## ⑦ 분량
- [ ] 공백 포함 **2500~3000자**가 적절(중앙값 2800 안팎 권장). 2500 밑돌면 근거·비유가 얇다는 신호 → 연구 수치를 체감형으로 보강. 3000 넘으면 군더더기 제거.
- 확인: `[System.IO.File]::ReadAllText($f,[System.Text.Encoding]::UTF8).Length`

## ⑧ 최종 검토 (발행 직전 — 5가지 자문)
완성본을 소리 내어 읽는다는 느낌으로 아래를 자문한다. 하나라도 "아니오"면 그 부분 재손질.
- [ ] **충분히 매력적인가?** 훅부터 끝까지 "다음이 궁금한" 힘이 있는가.
- [ ] **신선한 정보인가?** 헬스 좀 아는 사람도 "오 이 프레이밍은 몰랐네" 싶은 각도가 있는가. (뻔한 결론이면 프레이밍이라도 새롭게)
- [ ] **끝까지 볼 것 같은가?** 이탈 구간 점검. 특히 **비슷한 구조의 문단이 나란히 반복되면 늘어진다** → 하나로 합치거나 중간에 궁금증("그럼 둘 중 뭘?")을 걸어 리듬을 만든다.
- [ ] **어색한 데 없는가?** ⓐ 전문용어가 툭 튀지 않는가(쉬운 말/비유로), ⓑ 문단 도입부가 죄다 설명조로 평평하지 않은가(질문·전환 섞기), ⓒ 뜬금없는 문구 없는가(예: "헬스장에서 아무도 안 알려주죠" 같은 근거 없는 과장).
- [ ] **눈높이 맞는가? (친절 과잉 금지)** 구독자가 당연히 아는 개념을 모른다는 듯 풀어 설명하지 않는가. (예: 훅에서 이미 "5분할"을 언급했으면 "가슴·등·어깨·팔·하체를 요일마다" 식 나열 설명은 사족 → 축약/삭제)
- [ ] **구성 순서 점검**: "정리하겠습니다"류 마무리 뒤에 새 내용("마지막으로…")이 또 나오지 않는가. 실전 팁·주의사항은 정리 **앞**에 배치하고, 정리는 진짜 마지막에.

## 실제 개선 사례 (누적)
- **v1 직장인 분할편 (2026-09)**: 원본은 ①오프닝이 공감 묘사로 시작+인사 누락, ②서론에서 "분할 낮게 자주가 유리" 결론을 미리 공개, ④비유 부재가 문제였음. → 훅 신설("5분할 쪼개는 사람보다 2분할 직장인이 더 잘 큼")+인사 복원, 서론 결론 삭제하고 "끝까지 봐야 답" 예고로 전환, "성장신호=이틀 만에 꺼지는 알람" 비유 추가.
- **v1 2차 검토 (2026-09)**: ⓐ "헬스장에서 아무도 안 알려주죠" 뜬금없어 삭제("상식이랑 정반대죠"로), ⓑ "먼저 분할이 뭔지부터 짚겠습니다"는 친절 과잉이라 개념 설명 통째 삭제하고 바로 핵심(빈도)로 직행, ⓒ "정리하겠습니다" 뒤에 "마지막으로 배치 실수"가 또 나오는 순서 오류 → 배치 설명을 정리 앞으로 옮기고 배치 내용도 상술, ⓓ "근단백질 합성" 용어 완화, ⓔ 2·3분할 두 문단이 구조 반복이라 "그럼 뭘?" 궁금증으로 열어 하나로 통합.
